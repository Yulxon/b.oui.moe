Linux 发行版的开箱体验已经相当不错，但日常使用中仍会遇到不少细碎的问题。尤其是中文环境、网络代理和跨发行版的软件来源，往往需要手动调整，才能用得顺手。

本文整理了 Linux 桌面日常使用中的常见配置，涵盖网络代理、中文输入法与字体、软件管理和数据备份四个方面。示例以 NixOS + GNOME 为主，其中的声明式配置与发行版相关，但思路和大部分命令适用于其他发行版，文中会标注差异。

完整的 NixOS 配置可参考 [nixos-config](https://github.com/Yulxon/nixos-config)。

## 网络

部分网站需要通过代理访问，这涉及两件事：让软件走代理，再用分流规则让国内流量直连。

### 环境变量

大部分命令行软件会读取以下环境变量：

```bash
export http_proxy=http://127.0.0.1:7890
export https_proxy=http://127.0.0.1:7890
export all_proxy=http://127.0.0.1:7890
export no_proxy=localhost,127.0.0.1,::1
```

示例假定 mihomo 在 `7890` 端口提供 HTTP 或 Mixed 代理。不同软件对大小写的处理不一，个别软件只识别大写形式（如 `HTTP_PROXY`），遇到时再补一份即可。

环境变量只对当前 Shell 及其子进程生效，其他场景需要单独设置：

- **桌面软件和浏览器**：不一定继承终端里的变量。GNOME 可在「设置 → 网络 → 代理」中配置，浏览器也可以在自身设置中指定。
- **systemd 服务**：在服务单元中通过 `Environment=` 设置，或使用 `systemctl edit` 添加覆盖配置。
- **Git**：可单独配置，例如 `git config --global http.proxy http://127.0.0.1:7890`。
- **NixOS**：可通过 `networking.proxy.default` 为系统级服务统一设置。需要注意，Nix 守护进程拉取软件包时使用的是守护进程自身的环境，不是用户 Shell 的变量。

配置完成后，可以用 `curl -I https://github.com` 检查连通性。

此外，[MirrorZ Help](https://help.mirrors.cernet.edu.cn/) 收集了大量包管理器和开发工具的国内镜像配置。对于不方便走代理的场景，换镜像往往更省事。

### mihomo 配置

完整配置项参考 [mihomo docs](https://wiki.metacubex.one/config/)。

一份基本可用的配置包含三部分：

- `proxies`：代理节点，也可以通过 `proxy-providers` 载入订阅。
- `proxy-groups`：节点分组，支持手动选择或自动测速。
- `rules`：根据域名、IP 地址等条件决定流量去向。

还可以按需补充 `dns` 和 `tun`。`tun` 能接管不遵循系统代理设置的流量，但需要额外配置路由和权限。

例如：

```yaml
mixed-port: 7890
mode: rule

proxy-groups:
  - name: Proxy
    type: select
    proxies:
      - MyProxy
      - DIRECT

  - name: AI
    type: select
    proxies:
      - MyProxy
      - DIRECT
```

其中 `MyProxy` 需要替换为实际定义的节点名称。

首次启动时，mihomo 可能无法下载 GEO 文件，可以换一个下载地址：

```yaml
geox-url:
  geoip: https://testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/geoip.dat
  geosite: https://testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/geosite.dat
  mmdb: https://testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/country.mmdb
```

`GEOSITE` 规则可以使用 [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community/tree/master/data) 提供的域名集合。例如将 `category-game-platforms-download` 设为直连，可以改善 Steam 等平台的下载速度。

一个常见的分流思路如下：

```yaml
rules:
  - DOMAIN-SUFFIX,oui.moe,DIRECT
  - GEOSITE,category-ads-all,REJECT
  - GEOSITE,category-ai-!cn,AI
  - GEOSITE,category-game-platforms-download,DIRECT
  - GEOSITE,CN,DIRECT
  - GEOIP,CN,DIRECT
  - MATCH,Proxy
```

规则从上到下依次匹配，命中即停止，所以特殊规则要放在通用规则之前，兜底的 `MATCH` 放在最后。

需要注意：

- 广告拦截规则可能误伤个别网站，出现异常时可优先排查。
- GEO 数据可能滞后，可以开启 `geo-auto-update` 自动更新。
- 规则中的 `AI`、`Proxy` 必须与 `proxy-groups` 里定义的名称一致。

## 中文环境

Linux 软件优先适配英文，中文环境下常有输入法、异体字显示等问题，需要做些微调。

### 输入法

推荐使用 Rime 引擎，按桌面环境选择前端：

- GNOME：`ibus-rime`
- KDE 等：`fcitx5-rime`

NixOS 上可以声明式启用，以 GNOME 搭配 ibus 为例：

```nix
i18n.inputMethod = {
  enable = true;
  type = "ibus";
  ibus.engines = with pkgs.ibus-engines; [ rime ];
};
```

使用 fcitx5 时，将 `type` 改为 `"fcitx5"`，并通过 `fcitx5.addons = [ pkgs.fcitx5-rime ];` 添加引擎。

输入方案可按个人习惯选择，[雾凇拼音](https://github.com/iDvel/rime-ice)是维护活跃、开箱即用的方案之一。若想改善长句输入和候选词排序，可以启用 [万象语法模型](https://github.com/amzxyz/RIME-LMDG)，它依赖带有 octagram 插件的 librime，使用前请确认所用发行版的 Rime 已包含该插件。

在方案的 `*.custom.yaml` 中添加配置，例如：

```yaml
patch:
  grammar:
    language: wanxiang-lts-zh-hans
    collocation_max_length: 6
    collocation_min_length: 3
    collocation_penalty: -14
    non_collocation_penalty: -6
    weak_collocation_penalty: -100
    rear_penalty: -20
  translator/contextual_suggestions: true
```

再把对应的 `wanxiang-lts-zh-hans.gram` 放进 Rime 用户数据目录，重新部署即可生效。具体的文件名和参数，以模型版本及方案配置为准。

词库方面，可以用 [zhwiki](https://github.com/felixonmars/fcitx5-pinyin-zhwiki) 和 [moegirl](https://github.com/outloudvi/mw2fcitx) 补充专业词汇与流行用语；如果经常遇到生僻字，也可以启用雾凇拼音的 Unihan 大字表。

### CJK 字体

[Noto Fonts](https://fonts.google.com/noto) 能为多语言环境提供相对统一的视觉效果。建议安装 Noto Sans CJK、Noto Serif CJK 和 Noto Color Emoji，再补充 Symbols Nerd Font 用于显示图标。

一种常见的字体组合：

- **无衬线**：Noto Sans / Noto Sans CJK SC
- **衬线**：Noto Serif / LXGW WenKai
- **等宽及代码**：Maple Mono / Iosevka
- **符号和 Emoji**：Symbols Nerd Font / Noto Color Emoji

NixOS 中可以这样声明（包名随 nixpkgs 版本可能变化，以实际为准）：

```nix
fonts = {
  packages = with pkgs; [
    noto-fonts
    noto-fonts-cjk-sans
    noto-fonts-cjk-serif
    noto-fonts-color-emoji
    nerd-fonts.symbols-only
    lxgw-wenkai
  ];
  fontconfig.defaultFonts = {
    sansSerif = [ "Noto Sans" "Noto Sans CJK SC" ];
    serif = [ "Noto Serif" "Noto Serif CJK SC" ];
    emoji = [ "Noto Color Emoji" ];
  };
};
```

不过，只装字体还不够。

CJK 统一汉字（Han Unification）把中日韩共用的字符合并编码，但各地区的字形规范并不完全一致。如果 fontconfig 的回退顺序不合理，简体中文环境里就可能混入日文字形。

解决办法是为不同语言配置对应的字体族：默认使用 CJK SC，再根据语言标签选择相应变体：

| 语言 | 字体变体 |
|---|---|
| zh-CN、zh-SG | CJK SC |
| zh-TW | CJK TC |
| zh-HK | CJK HK |
| ja | CJK JP |
| ko | CJK KR |

在其他发行版上，可以把规则写入 `~/.config/fontconfig/fonts.conf`，例如为简体中文指定优先字体：

```xml
<match>
  <test name="lang"><string>zh-CN</string></test>
  <test name="family"><string>sans-serif</string></test>
  <edit name="family" mode="prepend"><string>Noto Sans CJK SC</string></edit>
</match>
```

其他语言按上表依次添加即可。fontconfig 的匹配与替换机制可以参考[这篇文章](https://catcat.cc/post/2021-03-07/)，也可以用[浏览器在线测试页](https://catcat.cc/raw/fontconfig.html)检查 CJK 字形。

### Flatpak 字体兼容

Flatpak 应用运行在沙箱里，可能读不到宿主机的 fontconfig 用户配置。授予只读权限即可：

```bash
flatpak override --user \
  --filesystem=xdg-config/fontconfig:ro
```

### Locale 设置

如果希望保留英文界面，同时启用中文输入和字体支持，可以让系统同时生成多个 Locale。NixOS 的写法如下：

```nix
i18n = {
  defaultLocale = "en_US.UTF-8";
  extraLocales = [ "zh_CN.UTF-8/UTF-8" ];
  extraLocaleSettings = {
    LC_MESSAGES = "en_US.UTF-8";
    LC_TIME = "en_GB.UTF-8";
  };
};
```

这样既能保留英文报错信息，也可以按需设置日期和时间格式（上例中时间格式使用 `en_GB`）。在其他发行版上，可通过 `/etc/locale.gen` 生成所需 Locale，再用 `localectl set-locale` 设置默认值。

## 软件管理

不管用哪个发行版，最后常用的软件大同小异。麻烦的是来源各不相同，更新机制也不统一。

### 软件来源

可以把软件分为三类：

| 类型 | 管理方式 |
|---|---|
| 系统软件 | apt、dnf、pacman、nix 等 |
| 桌面应用 | Flatpak |
| 项目依赖 | npm、pip、Cargo 等 |

通常用发行版的包管理器安装系统组件和命令行工具，桌面应用则优先考虑 Flatpak：它与发行版解耦，更新节奏独立，并带有沙箱隔离。常用命令如下：

```bash
flatpak install flathub org.example.App   # 安装
flatpak update                            # 更新全部
flatpak uninstall --unused                # 清理无用运行时
```

Flathub 访问较慢时，可以参考 MirrorZ Help 为 Flatpak 更换镜像。

开发依赖尽量避免全局安装：Python 使用虚拟环境，项目环境则可用 Nix 和 direnv 管理，以减少不同项目之间的依赖冲突。

### 浏览器与隐私

[LibreWolf](https://librewolf.net/) 是 Firefox 的加固分支，默认关闭遥测并内置反追踪。但它的默认设置偏保守：关闭时清除历史和 Cookie，同时禁用 WebGL 和 DRM。可以在保留隐私防护的前提下，只放宽影响体验的部分。以 Home Manager 为例：

```nix
programs.librewolf = {
  enable = true;

  settings = {
    # 保留历史记录和 Cookie
    "places.history.enabled" = true;
    "network.cookie.lifetimePolicy" = 0;
    "privacy.sanitize.sanitizeOnShutdown" = false;

    # 启用 WebGL 和 DRM
    "webgl.disabled" = false;
    "media.eme.enabled" = true;
  };

  policies = {
    # 使用独立的密码管理器
    PasswordManagerEnabled = false;
    DisableFirefoxAccounts = true;

    # 关闭遥测、实验和推荐内容
    DisableTelemetry = true;
    DisableFirefoxStudies = true;
    DisablePocket = true;
    FirefoxSuggest.SponsoredSuggestions = false;
  };
};
```

`settings` 对应 `about:config` 中的偏好项，`policies` 对应 Firefox 的[企业策略](https://mozilla.github.io/policy-templates/)，可以声明式地关闭一整类功能。

放宽选项会降低部分防护，例如 WebGL 可能被用于指纹识别，请根据自身需求权衡。非 NixOS 用户可直接在 `about:config` 或 `librewolf.overrides.cfg` 中设置同名选项。Profile 位于 `~/.librewolf`，备份时不要遗漏。

### Shell 增强

fish 配合 starship 是一套上手成本低的组合。fish 不兼容 POSIX，因此建议保留 bash 作为登录 Shell，只在交互式终端中切换到 fish：

```nix
programs.bash = {
  enable = true;
  initExtra = ''
    if [[ -t 0 && -t 1 ]] && grep -qv fish /proc/$PPID/comm && [[ $SHLVL == [12] ]]; then
        SHELL=${pkgs.fish}/bin/fish exec fish
    fi
  '';
};
```

这样脚本和 GUI 环境探测不受影响，`SHELL` 也会指向 fish，nix shell、tmux 等程序能正确识别。

```nix
programs = {
  fish = {
    enable = true;
    interactiveShellInit = "set -g fish_greeting ''";
    plugins = with pkgs.fishPlugins; [
      { name = "autopair"; src = autopair.src; }
      { name = "fzf-fish"; src = fzf-fish.src; }
    ];
  };

  starship = {
    enable = true;
    presets = [ "plain-text-symbols" ];
  };

  fzf.enable = true;     # Ctrl+R 搜索历史
  zoxide.enable = true;  # z 快速跳转目录
};
```

- **starship**：提示符，显示 Git 分支和命令状态。`plain-text-symbols` 预设不依赖 Nerd Font，在 TTY 和远程终端中也能正常显示。
- **fzf**：模糊搜索历史命令和文件。
- **zoxide**：记住常用目录，用 `z 关键词` 跳转。

另外，`fd`、`ripgrep`（更快的搜索）、`tealdeer`（命令速查）和 `btop`（资源监控）也是值得安装的日常工具。

## 数据备份

良好的备份习惯，既便于管理数据，也能应对硬盘故障、误删等突发情况。

### 备份原则

- **多份副本**：参考 3-2-1 原则，至少保留 3 份数据、使用 2 种不同介质、其中 1 份在异地。
- **自动执行**：依赖手动操作的备份迟早会被遗忘，应设置定期计划。
- **定期验证**：没有验证过的备份不可靠，应定期抽查并尝试恢复。
- **妥善保管密钥**：加密备份的密码或密钥丢失，数据将无法恢复，建议单独保存。

### 备份范围

可以将数据分为三类：

| 类型 | 常见目录或文件 |
|---|---|
| 系统配置 | `/etc`、NixOS 配置仓库 |
| 用户数据 | `/home` 下的文档、下载、项目等 |
| 应用状态 | XDG 配置和数据目录、浏览器 Profile 等 |

用户目录中的文件通常遵循 [XDG Base Directory](https://specifications.freedesktop.org/basedir-spec/latest/) 规范：

```text
~/.config       软件配置
~/.local/share  软件持久化数据
~/.local/state  软件运行状态
~/.cache        缓存
~/.var/app      Flatpak 应用数据
```

但并非所有应用都严格遵循。例如 SSH 密钥在 `~/.ssh`，Git 配置可能在 `~/.gitconfig`，还有些应用直接使用以点开头的隐藏目录。

一般来说，配置、文档、数据库和用户生成的内容需要备份，可以重新下载或生成的内容则可以排除，例如 `~/.cache`、回收站、`node_modules` 和构建产物目录。具体到个别软件：Rime 要保留用户词库和学习记录；浏览器则要考虑书签、配置，以及 Profile 中无法重新同步的数据。

对于 NixOS，系统本身可以由配置仓库重建，因此只要把配置仓库托管到远程（如 Git），系统层面几乎无需备份，重点放在用户数据和应用状态上。

### Pika Backup

桌面环境推荐 [Pika Backup](https://apps.gnome.org/PikaBackup/)。它基于 BorgBackup，支持增量备份、压缩、加密、备份计划和历史版本恢复。

配置也很简单：选择备份源、指定备份仓库、设置排除目录，之后就能定期自动执行。仓库可以是外置硬盘，也可以是通过 SSH 访问的远程服务器。

偏好命令行或需要在服务器上运行时，可直接使用 BorgBackup 或 restic，并配合 systemd timer 定时执行。以 Borg 为例：

```bash
borg init --encryption=repokey /path/to/repo
borg create --compression zstd \
  --exclude '~/.cache' \
  /path/to/repo::'{hostname}-{now}' ~/
borg check /path/to/repo   # 定期校验仓库完整性
```
