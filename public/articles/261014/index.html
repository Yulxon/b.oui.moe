Linux日常使用调优

Linux 发行版开箱即用的程度已经相当不错，但日常使用时仍会遇到一些细碎的问题。尤其是中文环境、网络代理和跨发行版软件兼容性，往往需要手动调整才能获得比较舒适的体验。

本文记录我在 Linux 桌面环境下使用过的一些配置与解决方案。主要使用 NixOS + GNOME，部分内容具有发行版特异性，但思路基本通用。

我的完整配置：nixos-config。

网络

由于众所周知的原因，部分网站需要通过代理访问。我们需要配置恰当的环境变量让软件走代理，以及合适的分流规则让国内流量走直连。

环境变量

大部分命令行软件遵循以下环境变量：

export http_proxy=http://127.0.0.1:7890
export https_proxy=http://127.0.0.1:7890
export all_proxy=http://127.0.0.1:7890
export no_proxy=localhost,127.0.0.1,::1

这里假定 mihomo 监听 7890 端口，并启用了 HTTP 或 Mixed 代理端口。

环境变量只对支持它的软件有效。浏览器、桌面软件以及 systemd 服务不一定继承终端中的环境变量。对于 GNOME，可以在系统设置中配置网络代理。

在 NixOS 中使用声明式配置：

networking.proxy.default = "http://127.0.0.1:7890";
networking.proxy.noProxy = "127.0.0.1,localhost,::1";

配置代理后，可以通过 curl -I https://github.com 检查连接。

如果软件下载缓慢，也不一定需要代理。MirrorZ Help 提供了大量软件包管理器及开发工具的国内镜像配置。

mihomo 配置

参考 mihomo docs。

一个基本可用的配置需要包含：

  • proxies：代理节点，也可以通过 proxy-providers 载入订阅。
  • proxy-groups：节点分组，支持手动选择或自动测速。
  • rules：根据域名、IP 地址等条件决定流量去向。

可选补充 dns 和 tun，后者能够接管部分不遵循系统代理设置的流量，但需要额外配置路由和权限。

例如：

mixed-port: 7890
mode: rule
allow-lan: false

proxy-groups:
  - name: Proxy
    type: select
    proxies:
      - MyProxy
      - DIRECT

  - name: AI
    type: select
    proxies:
      - MyProxy
      - DIRECT

其中 MyProxy 需要替换为实际定义的节点名称。

mihomo 首次启动可能无法下载 GEO 文件，可以尝试更换下载地址：

geox-url:
  geoip: https://testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/geoip.dat
  geosite: https://testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/geosite.dat
  mmdb: https://testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/country.mmdb

mihomo 的 GEOSITE 规则可以利用 v2fly/domain-list-community 提供的域名分类，其生成的数据也被相关 GEO 数据项目使用。

例如，category-game-platforms-download 包含部分游戏平台的下载域名，将其设为直连可以改善 Steam 等平台的下载速度。

下面是我使用的分流思路：

rules:
  - DOMAIN-SUFFIX,oui.moe,DIRECT
  - GEOIP,lan,DIRECT,no-resolve
  - GEOSITE,category-ads-all,REJECT
  - GEOSITE,category-ai-!cn,AI
  - GEOSITE,category-game-platforms-download,DIRECT
  - GEOSITE,CN,DIRECT
  - GEOIP,CN,DIRECT
  - MATCH,Proxy

规则按照顺序匹配，命中后便停止继续匹配，因此需要将特殊规则放在通用规则之前。

需要注意：

  • 广告拦截规则可能误伤网站资源。
  • IP 分流依赖 DNS 解析结果，域名分流通常更适合网站访问。
  • GEO 数据可能出现错误或滞后，必要时可以添加 DOMAIN-SUFFIX 规则进行覆盖。
  • 代理组 AI、Proxy 必须与实际配置中的名称一致。

如果终端能够正常联网，但某些应用无法访问网络，应先检查其是否遵循系统代理，而不是一开始就启用 TUN。

对于 NixOS，可以通过 services.mihomo 管理 systemd 服务。我将配置文件保留在 ~/.config/mihomo/config.yaml，而不直接写入 Nix 配置，避免包含节点密钥的文件进入公开仓库或 Nix Store。

sudo systemctl status mihomo
sudo journalctl -u mihomo -b -n 100

这两条命令可以用于检查服务运行状态和启动日志。

中文环境

Linux 软件对英文环境的支持普遍很好，但中文桌面环境仍存在输入法、字体回退以及异体字显示等问题。

多数情况下功能能够正常使用，却远远谈不上完善，需要进行一些微调。

输入法

中文输入推荐使用 Rime 引擎：

  • GNOME 环境可以使用 ibus-rime。
  • KDE 等桌面环境可以使用 fcitx5-rime。

输入方案可以按个人习惯选择，我比较偏好 雾凇拼音。

为了改善长句输入与候选词排序，可以启用万象语法模型。

在 Rime 方案的 *.custom.yaml 中添加相应配置，例如：

patch:
  grammar:
    language: wanxiang-lts-zh-hans
    collocation_max_length: 6
    collocation_min_length: 3
    collocation_penalty: -14
    non_collocation_penalty: -6
    weak_collocation_penalty: -100
    rear_penalty: -20

将对应的 wanxiang-lts-zh-hans.gram 放入 Rime 用户数据目录，重新部署后生效。具体文件名及参数仍应参考模型版本与方案配置。

词库方面，可以利用 zhwiki 和 moegirl 补充专业词汇与流行文化词汇，也可以考虑启用雾凇拼音的 Unihan 大字表，改善生僻字输入。

我的配置采用 NixOS 提供输入法引擎、方案和词库，再由 Home Manager 管理 Rime 用户配置的方式。这样可以减少手动更新词库的工作量，也便于在不同设备间复用配置。

注意区分 Rime 的配置文件和运行时数据。*.userdb 中的用户词频与学习记录不适合被声明式配置覆盖，迁移系统时应单独保留。

CJK 字体

Noto Fonts 能够为多语言环境提供相对统一的视觉效果。推荐安装 Noto Sans CJK、Noto Serif CJK、Noto Color Emoji，并补充 Symbols Nerd Font 来显示图标。

个人偏好的字体组合：

  • 无衬线：Noto Sans / Noto Sans CJK SC
  • 衬线：Noto Serif / LXGW WenKai
  • 等宽及代码：Maple Mono / Iosevka
  • 符号和 Emoji：Symbols Nerd Font / Noto Color Emoji

不过，仅仅安装字体还不够。

CJK 统一汉字编码包含中日韩共用的字符，但各地区的字形规范并不完全一致。fontconfig 的字体回退不合理时，就会出现简体中文环境下混入日文字形的情况。

因此需要为不同语言配置相应的字体族。默认使用 CJK SC，同时根据语言标签选择对应变体：

语言 字体变体
zh-CN、zh-SG CJK SC
zh-TW CJK TC
zh-HK CJK HK
ja CJK JP
ko CJK KR

可以参考这篇文章了解 fontconfig 的匹配和替换机制。

用浏览器在线测试 CJK 字形。

对于 NixOS，还可以通过 Home Manager 的 fonts.fontconfig.defaultFonts 配置默认字体族，而不必逐个修改应用程序。

Flatpak 字体兼容

Flatpak 应用运行在沙箱环境中，可能无法正确读取宿主机的 fontconfig 用户配置。

可以授予只读权限：

flatpak override --user \
  --filesystem=xdg-config/fontconfig:ro

此外，NixOS 的字体存放在 Nix Store 中，部分 Flatpak 应用可能无法正确发现这些字体。

优先通过 fonts.packages 在系统级安装字体。若仍然缺失，可以检查 /run/host/fonts，再考虑额外的 fontconfig 字体目录配置。

我在自己的配置中还针对 Flatpak Chrome 设置了独立的字体扫描路径，具体参考 fontconfig.nix。

不要为了修复一个字体问题就直接开放整个主目录的沙箱权限。

Locale 设置

不一定需要将整个系统切换为中文。我的习惯是保留英文界面，同时启用中文输入和字体支持。

NixOS 可以同时启用多个 Locale：

i18n = {
  defaultLocale = "en_US.UTF-8";
  extraLocales = [ "zh_CN.UTF-8/UTF-8" ];
  extraLocaleSettings = {
    LC_MESSAGES = "en_US.UTF-8";
    LC_TIME = "en_GB.UTF-8";
  };
};

这样既保留英文报错信息，也能够按个人习惯设置日期和时间格式。

软件管理

无论使用何种发行版，最终常用的软件基本类似。比较麻烦的是软件来源可能不同，更新机制也不完全统一。

软件来源

可以把软件分为三类：

类型 管理方式
系统软件 apt、dnf、pacman、nix 等
桌面应用 Flatpak
项目依赖 npm、pip、Cargo 等

通常优先使用发行版的包管理器安装系统组件和命令行工具，桌面应用则可以考虑 Flatpak。

对于开发依赖，尽量避免全局安装。

Python 可以使用虚拟环境，Node.js 项目可以使用项目级依赖。使用 Nix 时还可以结合 nix develop、direnv 和 nix-direnv，实现进入项目目录时自动加载开发环境，离开后恢复原来的环境变量。

这样可以减少不同项目之间的依赖冲突。

兼容性

NixOS 的文件系统布局与传统 Linux 发行版存在区别，因此部分直接下载的二进制程序可能无法运行。

可以启用 nix-ld，为依赖传统动态链接器路径的 ELF 程序提供兼容环境：

programs.nix-ld.enable = true;

如果程序仍然缺少动态库，可以通过 programs.nix-ld.libraries 补充依赖。

但 nix-ld 不能保证所有预编译 Linux 软件都正常工作。对于依赖复杂运行环境的工具，也可以考虑容器化。

更新与回滚

对于滚动发行版，更新意味着持续接受新版本；对于固定发布周期的发行版，则主要是安全更新和定期升级。

NixOS 的 Flakes 使用 flake.lock 固定依赖版本，能够更方便地控制更新范围。

以我的配置为例：

# 更新主要输入
nix flake update nixpkgs home-manager

# 检查配置
nix flake check --no-build path:.

# 应用系统配置
sudo nixos-rebuild switch --flake .#asus

其中 asus 是主机配置名称，实际使用时需要替换。

更新其他独立输入需要分别指定，例如：

nix flake update llm-agents

不建议每次都无差别更新全部依赖。

如果新配置出现问题，可以使用：

sudo nixos-rebuild switch --rollback

或者从引导菜单选择之前的系统代。

注意 system.stateVersion 和 home.stateVersion 是兼容性选项，并不是当前软件版本。日常更新 Nixpkgs 时不应顺手修改它们。

Flatpak 则有独立的更新方式：

flatpak update
flatpak uninstall --unused

第二条命令会移除当前不再被使用的运行时和扩展，执行前可以检查待删除内容。

确认系统运行稳定之后，再清理不需要的 Nix generations 和 Store 数据，避免过早丢失可用的回滚版本。

数据备份

Linux 的软件和配置比较容易重新部署，但个人数据和应用状态未必能够恢复。

特别是对 NixOS 而言，声明式配置只能重建被声明的部分，不能替代数据备份。

备份范围

可以将数据分为三类：

类型 常见目录或文件
系统配置 /etc、NixOS 配置仓库
用户数据 /home 下的文档、下载、项目等
应用状态 XDG 配置和数据目录、浏览器 Profile 等

需要特别注意，/root 是 root 用户的主目录，并不代表整个系统。

用户目录中的文件通常遵循 XDG Base Directory 规范：

~/.config       软件配置
~/.local/share  软件持久化数据
~/.local/state  软件运行状态
~/.cache        缓存
~/.var/app      Flatpak 应用数据

但并非所有应用都会严格遵循 XDG 规范。例如 SSH 密钥可能位于 ~/.ssh，Git 配置可能位于 ~/.gitconfig，部分应用还会直接使用以点开头的隐藏目录。

一般而言，配置、文档、数据库和用户生成的内容需要备份，能够重新下载或生成的缓存则可以排除。

对于 Rime，应当保留用户词库与学习记录；对于浏览器，则需要考虑书签、配置和 Profile 中无法重新同步的数据。

Pika Backup

桌面环境推荐使用 Pika Backup。

它基于 BorgBackup，支持增量备份、压缩、加密、备份计划和历史版本恢复。

配置起来比较简单：选择备份源、指定备份仓库、设置排除目录，之后便可以定期自动执行。

建议将主要用户目录纳入备份，排除不必要的构建产物和缓存，例如：

~/.cache
~/.local/share/Trash
node_modules
target
__pycache__

实际排除规则要结合软件和项目情况调整，不能无差别排除所有隐藏目录。

备份仓库最好位于另一块物理磁盘或远程服务器，而不是与原始数据保存在同一设备上。

如果使用加密备份，务必妥善保存密码或恢复密钥。

同时，备份的目的并不是成功生成一个归档文件，而是在系统损坏时能够完整恢复数据。因此最好定期尝试恢复少量文件，检查备份是否可用。

NixOS 配置备份

声明式配置适合使用 Git 管理，配合 flake.lock 可以记录软件依赖版本。

不过，Git 仓库一般只应该保存可公开或可安全同步的配置，不应该包含密码、Token、SSH 私钥和代理节点凭据。

个人数据使用 Pika Backup，系统配置使用 Git，两者相互补充。

对于使用 Btrfs 的系统，还可以通过快照实现快速回退，但快照不能替代异地备份：硬盘损坏时，同一块磁盘上的快照也可能全部丢失。

日常维护

最后补充几个日常排查命令。

日志与服务

# 查看启动期间的错误
journalctl -b -p err

# 查看指定服务
systemctl status mihomo

# 查看用户服务
systemctl --user --failed

# 查看磁盘空间
df -h

# 查看目录占用
du -sh ~/.cache ~/.local/share ~/.var/app 2>/dev/null

出现异常时，先检查日志往往比直接重装软件更有效。

还可以定期检查磁盘剩余空间、系统更新和备份状态。对于长期运行的桌面系统，这些基础维护通常比激进的内核参数调优更有价值。

结语

Linux 桌面的使用体验往往取决于许多细节。网络代理、输入法、字体、软件依赖与备份机制都不算复杂，但初次配置时很容易消耗大量精力。

对我而言，比较理想的状态是：大部分系统配置能够声明式管理，用户数据有独立备份，不同项目之间尽量隔离依赖，软件更新也有明确的回滚方案。

把这些问题一次性整理好，以后就可以少折腾环境，把时间留给真正想做的事情。
